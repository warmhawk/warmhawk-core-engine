# Changelog

All notable changes to `warmhawk-core-engine` are documented here. The dashboard
(`warmhawk-enterprise-operator`) shows an "update available" banner by comparing its running
version against this repo's latest GitHub release tag — keep this file current on every release,
not just as a courtesy.

Format loosely follows [Keep a Changelog](https://keepachangelog.com/), versions follow semver.

## [Unreleased]

### Added — auth bridge for warmhawk-enterprise-operator's dashboard

- **`OPERATOR_SERVICE_TOKEN`**: warmhawk-enterprise-operator's dashboard had no credential to
  authenticate against this engine's `/v1/*` routes at all (its dashboard login is a separate,
  local system with no `User` row here) — every real-data page 401'd in that repo. Fixed with a
  shared long-lived secret `lib/requireAuth.ts` accepts as an alternative to a signed JWT, same
  pattern as `NEXTJS_CALLBACK_SECRET` already uses for n8n. Generated by `scripts/install.sh`
  alongside the other secrets; optional (Tier-0-only installs are unaffected). Added
  `apps/api/src/__tests__/unit/requireAuth.test.ts` as a regression guard.

### Fixed — reply-poll correlation regression, internal-route exposure

- **Reply Management correlation was silently dead for every send made after the privacy fix.**
  `routes/replies.ts`'s `/pending` endpoint (n8n reply-poll's correlation source) read
  `payloadSent.subject` to build an IMAP search term, but `lib/mailSender.ts`'s privacy fix (see
  below) had already stopped writing that field — every candidate was silently skipped, and no
  test caught it since route-level behavior here was previously untested. Fixed properly rather
  than reverted: `ExecutionLog.providerMessageId` now records nodemailer's Message-ID (an opaque
  id, not personalized content, so the privacy fix's intent is preserved), and correlation is done
  via IMAP's standard In-Reply-To/References header search (`routes/imap.ts`) instead of a
  subject-substring heuristic. Added `apps/api/src/__tests__/unit/internalReplies.test.ts` as a
  regression guard.
- **`GET /replies/pending`, `POST /replies`, and all of `imap.ts`'s routes were mounted under the
  public `/v1` group** despite being n8n-machine-only (`requireCallbackSecret`, not dashboard
  JWT) — `/v1/replies/` has an explicit nginx location block, so the two `replies` routes were
  genuinely externally reachable (behind the callback secret only, not network isolation);
  `/v1/imap/*` had no nginx block and so wasn't externally exposed, but relied on that omission
  alone rather than living under `/internal/*` like every other machine-only route. Split into
  `routes/internalReplies.ts` (`GET /internal/replies/pending`, `POST /internal/replies`) and
  remounted `imap.ts` at `/internal/imap`; `n8n/workflows/reply-poll.json` updated to match.

### Added — API surface correction, guardrail wiring, real AI BYOK, infra

- **`/v1` API prefix** (hard cutover) across every route, nginx, n8n workflows, the operator
  dashboard's API client, and the e2e-install script. Path-shape fixes to match spec:
  `/webhooks/leads` -> `/v1/leads/webhook`, `/queue/overview` -> `/v1/queue/status`, unified
  `POST /v1/domains/:domain/check` (replacing two separate id-keyed routes).
- New endpoints: `POST /v1/leads` (single-lead create), `DELETE /v1/leads/erase` (GDPR bulk
  anonymization — PII nulled, `piiErasedAt` set, aggregate counts preserved), `POST
  /v1/campaigns/:id/launch|pause`, `POST /v1/queue/pause`. `GET /v1/campaigns` now returns
  per-campaign aggregates (leads/sent/replies/domains/last-activity).
- Removed the vestigial license-issuance flow from `scripts/install.sh`/`tests/e2e-install` (`
  --license`, RSA keypair generation, `/auth/activate` polling) — Tier 0 carries no license gate;
  this logic never belonged in this repo (license issuance lives in `warmhawk-site`, verification
  in `warmhawk-enterprise-operator`).
- Wired two previously-orphaned guardrails into their real call paths: the bounce circuit breaker
  (`lib/bounceCircuitBreaker.ts`, dual-scope — mailbox-level auto-flag, campaign-level auto-pause)
  in `lib/mailSender.ts` and the worker's enqueuer; spam-score/spintax validation in
  `routes/campaigns.ts` create/update. Fixed a live privacy bug — AI-personalized email bodies
  were being persisted indefinitely in `ExecutionLog.payloadSent`; now only lengths are logged.
- Real AI BYOK: `lib/aiProviders/gemini.ts` and `claude.ts` (plain `fetch`, no SDK) replace the
  previous stub for key validation, personalization, and reply classification. Personalization
  retries once on failure, then falls back to the raw template and flags
  `aiPersonalizationFailed` rather than blocking the send.
- OTEL SDK wired into `apps/api` and `apps/worker` (`otel.ts`, default-on/inert until
  `OTEL_EXPORTER_OTLP_ENDPOINT` is set).
- Uptime Kuma is now actually provisioned on install, not shipped blank: new `packages/ops-scripts`
  workspace (`provisionUptimeKuma.ts`, drives Kuma's Socket.IO API — it has no REST write API) and
  a `kuma-provision` one-shot Compose job, run by `install.sh` right after the container comes up.
  Creates an admin account, one monitor per internal service (nginx/api/n8n/postgres/redis, 60s
  interval), and an optional webhook alert notification (`UPTIME_KUMA_ALERT_WEBHOOK_URL`).
- `n8n/workflows/blocklist-poll.json` (new) — hourly DNSBL re-check for every domain, via new
  `GET /internal/domains/active` / `POST /internal/domains/check-blocklist` routes.
- `scripts/restore-postgres.sh` (new, mirrors `backup-postgres.sh`) — verified against a real
  restore drill, not just written.
- Added `.dockerignore` — every `Dockerfile.*` uses `context: .` with nothing previously excluding
  `node_modules`/`.git`, inflating every image build's context transfer by 10x+.

### Added — real n8n workflows, install/load test harnesses, Seed-Inbox Placement Test

- `n8n/workflows/dispatch.json` and `reply-poll.json` rewritten as real, fully-wired node graphs
  (no more skeleton/placeholder nodes) calling this repo's own internal API exclusively; new
  `n8n/workflows/seed-placement-poll.json`. Two small internal-only routes were added to make this
  possible: `GET /internal/mailboxes/active` and `GET /replies/pending`.
- `POST /internal/mail/send` (`apps/api/src/lib/mailSender.ts`) — the actual SMTP/OAuth send-
  trigger endpoint the dispatch workflow calls: enforces CAN-SPAM compliance, attaches RFC 8058
  headers, applies the EU AI disclosure marker, fires the Seed-Inbox Placement Test BCC hook, and
  records the Lead/`ExecutionLog` outcome (sent / hard-bounced / soft-failed-with-retry).
- Seed-Inbox Placement Test (Guardrails, V12, option (c) — "placement sampling"): `SeedAccount` +
  `SeedPlacementResult` models, `GET/POST/PATCH/DELETE /seed-accounts`, the BCC send-pipeline hook,
  the IMAP folder-classification polling job (`lib/seedPlacementPoller.ts`), and
  `GET /domains/:id/placement-sample` — honestly labeled "placement sampling across N seed
  inboxes," never full inbox-placement testing.
- Complete `tests/e2e-install/run.sh` (install-flow e2e, release-gated — needs a real VM/CI
  runner + DNS to actually execute) and a Mailpit test overlay (`docker-compose.e2e-install.yml`).
- Complete, versioned `tests/load/dispatch-load-test.js` (k6) with two realistic scenarios and
  loudly-marked TODO threshold placeholders pending a real measured hardware baseline.
- Fixed a latent dependency-drift bug blocking every integration test: `@fastify/helmet`/
  `@fastify/rate-limit`'s caret ranges had resolved to majors that require Fastify 5, while this
  repo runs Fastify 4 — pinned back to the last Fastify-4-compatible majors (`^11.1.1`/`^9.1.0`).

### Added — initial foundation build

- Fastify API (`apps/api`) and BullMQ worker (`apps/worker`) scaffolding, ported/adapted from
  outreach-infra's Express-based equivalent (see build report for the framework judgment call).
- Prisma schema (`packages/db`) — Lead, Campaign, Domain, Mailbox, SuppressionEntry,
  ExecutionLog, User, AiProviderKey, Reply, License, InstanceSettings.
- `packages/tier-config` — single source of truth for Tier 0/1/2 feature gating, shared shape
  with `warmhawk-enterprise-operator`.
- Cadence/jitter math (`computeNextSlotSeconds.ts`) and weighted mailbox rotation
  (`enqueuer.ts`), ported forward with full unit test coverage.
- Redis Durability: AOF `ops/redis.conf`, bounded BullMQ job retention, and a crash-recovery
  reconciliation cron (`reconcile.ts`).
- `POST /leads/import` (CSV, injection-defended, chunked batch insert) and the shared
  `leadIngest.ts` validation function used by both the CSV and webhook ingest paths.
- BYOK AI personalization (`GET/POST/DELETE /ai-providers`, internal
  `/internal/ai/personalize`) with a stubbed (never-live) provider-call interface.
- Reply Management foundation: `Reply` model, extended `imap.ts` (fetch-reply), internal
  `/internal/ai/classify-reply`, opt-out-to-suppression wiring.
- Guardrails enforced structurally: CAN-SPAM auto-injection gate, RFC 8058 header generation,
  CSV injection defense, GDPR hard-delete (`DELETE /leads/:id`), EU AI Act Article 50 disclosure
  marker, bounce/complaint circuit breaker evaluation, login brute-force throttle.
- Continuous blocklist/DNSBL monitoring (Spamhaus ZEN/DBL, Barracuda, SORBS) extending the
  ported SPF/DKIM/DMARC checker.
- Google Workspace OAuth ported forward; Microsoft 365 OAuth built new (Entra app registration
  is an external, unblocked-but-pending dependency — see build report).
- Stripe webhook skeleton issuing RSA-signed licenses on `checkout.session.completed`/
  `invoice.paid`; natural expiry (no active revocation) on payment failure/cancellation.
- Free public domain-check backend (`GET /public/domain-check`).
- Containerization: internal-only Docker network, bundled nginx+certbot (the only published
  ports), bundled Uptime Kuma, OTEL env wiring, digest-pinned base images, resource limits.
- `scripts/install.sh` (idempotent, preflight-checked, multi-condition go/no-go, degrade-not-
  crash TLS), `scripts/update.sh`, `scripts/backup-postgres.sh` +
  `docs/backup-and-restore.md`.
- CI: self-contained GitHub Actions workflow, ESLint flat config, Prettier, serialized
  integration-test config.
- `security.txt` (RFC 9116) at repo root and `.well-known/`.
